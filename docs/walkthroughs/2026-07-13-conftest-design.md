## Decisions

| # | Section | Settled |
|---|---------|---------|
| 1 | **bootstrap** | 3-line bootstrap: `__file__`-anchored `sys.path.insert` of `framework/` + `load_dotenv(PROJECT_ROOT/.env)`. No editable install (survives prod-test repo copies). No vendored site-packages. Imports relative to `framework/` root. |
| 2 | **cli-options** | `pytest_addoption`: `--env`, `--headless`, `--browser` (each CLI > env var > default) + `--scenario-dir` for per-run scenario data injection. Fresh name and fresh implementation (renamed from v2's `--data_dir` concept for zero vocabulary echo). |
| 3 | **config** | Session-scoped config fixture: stdlib `json` + `pathlib`, keyed by `--env`, explicit `ValueError` on unknown env. One environment block carries per-interface sections (`url`, `api_base_url`, `database`, `soap_wsdl`). Values only — secrets never in config. Config JSON schema itself is Phase 3.1. |
| 4 | **fixture-placement** | Fixture definitions live once as modules under `framework/` loaded via `pytest_plugins` in root conftest — sibling conftests can't compose (evidence: v2 tools/conftest.py is a verbatim copy of tests/conftest.py). |
| 5 | **credentials** | Role-keyed `users` dict per environment, each `{username, password_env}`; ONE session-scoped credentials fixture resolves all users up front (fail-fast, naming missing vars); Roles receive identity via fixtures — the Interface never sees users. **DB and API authenticate as users too** (per-user identity, e.g. analyst's own SQL login), not service accounts — factories take an identity from the same users dict; config names each interface's default identity. `.env.example` lists every secret var. |
| 6 | **logging** | Session-scoped logger fixture: named logger `hmsa-qa` (never root), console INFO + file DEBUG to `reports/test_run.log` (single file, overwritten; CI archives artifacts), `if not log.handlers` guard, timestamps both formatters, worker-suffixed under xdist. Interfaces receive the logger via constructor; `@trace` writes into the same logger. Correlation IDs / JSON / masking deferred to Phase 3.8 — the fixture is the seam. |
| 7 | **interfaces** | Scope map: browser/driver FUNCTION-scoped (accumulates test state; fresh per test, `quit()` teardown); db/api/soap SESSION-scoped (stateless pipes, expensive to open). Explicit teardown (`yield` + `close()`), never `del`. Fixtures call Phase 3.5 factories. **DB write discipline: explicit cleanup** — transaction rollback REJECTED (uncommitted setup rows invisible to the app's own connection, breaks DB→UI→DB hybrid flows). Cleanup mechanics in Phase 3.3. |
| 8 | **layer-stack** | Full-stack fixtures: every L2/L3/L4 object gets a function-scoped two-line fixture — domain objects in domain conftest, interfaces + generic shared components in `framework/fixtures/`. **Same-instance rule, written explicitly:** tests assert through the same fixture instances their Tasks consumed (L2 state is meaningless on a fresh copy). Dual assertion pattern (typed result AND L2 state-checks) shown in the design doc. ~7 defs per domain, flat regardless of test count, agent-generated. |
| 9 | **report-hooks** | Screenshot-on-failure via `pytest_runtest_makereport` hookwrapper with two guards (`when=='call'` + `'browser' in fixturenames`), to `reports/screenshots/{test}{worker}.png`, attached to pytest-html. HTML title + metadata hooks copied verbatim from platform-selenium. Non-UI evidence = the DEBUG log. Allure deferred (3.4). Rationale kept: logs record what the code did; screenshots record what the app showed. |
| 10 | **markers** | Dynamic marker registration copied verbatim from platform-selenium (AST scan at `pytest_configure`) + curated core set in `pyproject.toml` (`smoke`, `regression`, `ui`, `api`, `db`, `soap`). No `--strict-markers`. Typo trade-off accepted for the agent-generates-tests model. Domain markers match domain folder names. |
| 11 | **domain-conftest** | Readmissions conftest is the template: domain constants → parametrize tuples → layer fixtures + committed `data/` per domain (role-keyed JSON where workflow-shaped). **Collection-vs-runtime rule:** parametrize tuples must be module-level constants (collection precedes fixtures); scenario content loads via fixture. `--scenario-dir` = directory override mirroring the domain `data/` layout (onboard runs, prod-pulled data), else committed default. Zero hardcoded names in test files. |

## Notes & Deferred

- **RATIFIED REFINEMENT (post-walkthrough, tasks-db dry run, 2026-07-13):** §11's "domain constants (SP names, table names...)" narrows — *test-shaping values* (variant keys, expected outcomes) live in the domain conftest; *identifiers* (SP names, table names) live in the Data Object's constants, per contract L3 rule 10 + SQL addendum. SP name : Data Object :: locator : Page Object. The readmissions conftest is the right pattern with the wrong contents. SP names exist only for SP-as-subject testing (SIT); E2E tests never name them — they observe effects.

- **Dry run (layer-stack):** stress-tested against real autopend TC-001 (test-cases-sit-pb.xlsx) — DB + UI + claim-injection hybrid; 7 domain fixtures cover all ~30 autopend TCs; scales one fixture def per added interface (3 interfaces verified, SOAP/REST extrapolated).
- **Deferred to Phase 1/Phase 4:** claim-injection mechanism — likely the **837BT tool** (per user), not a straight EDI file drop, so a FileInterface (interface #5) may not be needed. Resolve when the Phase 4 harness / client intake path is defined.
- **Parked for Phase 3.3:** DB cleanup mechanics (who deletes, when, replayability flag); scenario-dir single-vs-set granularity within a run.
- **Structural decision made mid-walkthrough:** interface addenda merged into 5-layer-contract.md (v2.2) — one md = one backlog = one pipeline deliverable in `02-reference-patterns/`.
- **No reference repo implements the clean version** of credentials, logging, or L2+ fixtures — those sections are fresh design mandated by contract v2.1; bootstrap/cli/config/interfaces/report-hooks/markers are platform-selenium patterns adopted or extended.
