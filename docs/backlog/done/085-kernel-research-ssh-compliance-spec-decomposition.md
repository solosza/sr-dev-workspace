# Research: Decompose SSH Compliance Frameworks into Domain Spec

## Status
Open

## Priority
High — compliance frameworks are built and tested in platform-ssh-test but not yet in the platform-ssh domain spec

## Summary
Research how to decompose the 8 compliance framework validators (STIG, CIS, NIST, FIPS, PCI DSS, HIPAA, SOC 2, ISO 27001) from the test repo into the platform-ssh domain spec. The test repo (`platform-ssh-test`) has 13 validators and 88 rules across 8 frameworks. The domain spec (`platform-ssh`) only has the original 4 validators. Need to determine the right spec architecture — how to represent compliance frameworks, fixtures, and the ComplianceValidator base class in the domain spec so that `domain-setup` produces them correctly when applied to a new workspace.

## Requirements
- Analyze the platform-selenium domain spec as a reference for how a mature spec handles multiple components (pages, roles, tasks, tests)
- Map the SSH compliance architecture (ComplianceValidator → framework validators → JSON fixtures → tests) to the domain spec pattern
- Determine: should each framework be a separate step in the spec workflow, or should the base class + all frameworks be one step?
- Determine: should fixture JSON files be embedded in the spec or generated by the agent during domain-setup?
- Determine: how does the spec reference the `frameworks` field in host_configs.json to drive which validators run?
- Determine: should the spec workflow have a "compliance audit" step that runs all enabled frameworks?
- Produce a research document with: proposed spec structure, file mapping, workflow changes, and migration plan
