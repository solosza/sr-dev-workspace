# Composition Architecture: prod-test + platform-deepeval

## Status
NEW

## Purpose

Define how prod-test Step 6 composes the platform-deepeval spec into the test repo so L3 tests use DeepEval as the evaluation engine.

## Current State

**prod-test** creates a test repo structure:
```
[source]-test/
├── .claude/skills/[domain-spec]/    ← domain spec from source repo
├── .claude/commands/kernel/          ← kernel commands
├── _test/
│   ├── tasks/                        ← L1/L2/L3 inner test tasks
│   └── validation-report.json        ← final report
└── [source files]
```

**platform-deepeval** has its own structure:
```
platform-deepeval/
├── .claude/skills/deepeval-management-layer/
├── framework/
│   ├── interfaces/deepeval_interface.py
│   ├── _reference/                   ← reference implementations
│   └── resources/                    ← config, metric defaults
└── tests/                            ← eval test files
```

## Composed Structure

When L3 is enabled, the test repo gets both specs:
```
[source]-test/
├── .claude/skills/
│   ├── [domain-spec]/                ← source repo's domain spec
│   └── deepeval-management-layer/    ← copied from platform-deepeval
├── framework/                         ← copied from platform-deepeval
├── eval/                              ← generated by L3 tasks
│   ├── goldens/                      ← translated from contract JSONs
│   ├── metrics/                      ← generated Metric Objects
│   ├── tests/                        ← generated pytest eval files
│   └── results/                      ← eval output + scores
├── _test/
│   ├── tasks/                        ← L1 + L2 + L3 inner tasks
│   └── validation-report.json        ← includes DeepEval scores
└── [source files]
```

## Composition Steps (inside prod-test Step 6)

1. **Detect L3 eligibility.** Check if source repo has contract JSONs in any skill's `contracts/` folder. If yes, L3 deepeval is available. If no contracts, skip L3 (L1/L2 only).
2. **Copy platform-deepeval spec.** Copy `.claude/skills/deepeval-management-layer/` and `framework/` from platform-deepeval into the test repo.
3. **Translate contracts to goldens.** Run the golden dataset translator (see `golden-dataset-translator.md`) against each contract JSON. Output to `eval/goldens/`.
4. **Write L3 inner tasks.** Generate tasks that invoke the deepeval eval-workflow command to: select metrics (Agent pipeline), generate eval suite from goldens, run tests.
5. **L3 tasks execute during Step 7.** Inner `run-task.sh` processes L3 tasks alongside L1/L2.

## Key Decision: Detection vs Flag

**Options:**
- a) Auto-detect: if contracts/ exists, enable L3
- b) Flag: `--l3-deepeval` on prod-test invocation
- c) Config: `prod-test-config.json` in source repo

**Recommendation:** (a) Auto-detect. Contracts are the bridge. If they exist, the source repo has declared expected behaviors, and those can be evaluated. No flag needed.

## Dependencies

- platform-deepeval must be at a known path (or discoverable)
- Golden dataset translator must exist
- Agent output capture must work (see `agent-output-capture.md`)
