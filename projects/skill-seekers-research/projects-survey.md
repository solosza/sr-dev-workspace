## Skill Packaging Candidacy

### Strong Candidates (Tier 1 — ready to package)

Projects that have:
1. Multiple structured sub-files with headers and conclusions
2. A synthesis report with Go/No-Go or actionable recommendations
3. Clear domain boundaries

**11 projects qualify:** ai-business-formation, ai-clone-opportunity, ai-ugc-research, business-credit-research, custom-game-emoji-research, geo-services-research, govcon-research, hoi-an-knockoff-shirts, hoi-an-leather, nav-consolidation-research, kernel-architecture.

### What's Missing for Skill Packaging

Current projects are **research outputs** (markdown reports), not **callable workflows**. To package them as skills, each would need:

1. **SKILL.md** — identity, step table, file index
2. **Input contract** — what triggers the skill (e.g., "user asks about LLC formation")
3. **Output contract** — what the skill produces (e.g., "Go/No-Go recommendation with rationale")
4. **Workflow steps** — how to get from input to output (currently implicit in the research process)
5. **Reference data** — the research findings become reference files the skill consults

The gap is: existing projects document **findings** but not the **process that produced them**. A skill needs both — the process (repeatable workflow) and the knowledge (reference data).

### Two Packaging Models

**Model A: Knowledge Skill** — The research outputs become reference files that an agent consults when asked about the topic. No workflow, just indexed knowledge. Example: "What's the legal risk of importing knockoff shirts?" → agent reads hoi-an-knockoff-shirts/legal-compliance.md and synthesizes an answer.

**Model B: Research Template Skill** — The research *process* becomes a repeatable skill that can be applied to new topics. The existing research becomes example output. Example: "Research the feasibility of X business" → skill follows the same numbered-file + synthesis-report pattern used across all Tier 1 projects.

Model B is more powerful — it captures the pattern that already exists implicitly across 11 projects.

---

## Key Finding

The workspace already has a de facto research template: **numbered topic files → synthesis report → Go/No-Go recommendation.** This pattern emerged organically across 11+ projects. Formalizing it as a callable skill (Model B) would make future research projects structurally consistent from the start, rather than hoping the pattern gets followed.
