# Data Angle-Loop

**Purpose:** For an idea, answer *"how does the data this generates become an asset, revenue stream, or moat?"* Part of the `/expand` family.
**Philosophy:** generative — dream the biggest data play; the adversarial loops test it.

## Cross-cutting rules
- **THINK BIGGER.** The empire data-play, not a report export — every way the data monetizes the space + compounds into a moat no competitor can copy.
- **LEAN OUTPUT** ([[loop-output-lean]]). **Standalone & modular** (alone or called by `/expand`). **Generative, not kill-by-default.** **Every run saved.**
- **Capture new angles.** Spot a monetization/expansion path with NO existing angle-loop? Append it to `projects/assay/loop-candidates.jsonl` — `/sharpen` promotes recurring ones into new loops.

## Steps
| # | Step | Do |
|---|------|-----|
| 1 | What data | What proprietary data does running this generate (usage, outcomes, behavior, benchmarks)? |
| 2 | Who wants it | Who would pay for it or the insight from it (customers, vendors, investors, the market)? |
| 3 | The play | Sell it · a data product/dashboard · a benchmark/index · a network-effect moat (more users → better data → more users). |
| 4 | Cheapest test | The smallest way to prove someone values the data (a teaser benchmark, a pre-sold report). |

## Output (lean)
1. **The data asset** (1 line — what compounds).
2. **The play + who pays** (1-2 lines).
3. **The moat** (does it network-effect?).
4. **Cheapest test.** One line: pursue?

## Persist (compact)
- **Report** -> `projects/assay/data/runs/<YYYY-MM-DD>-<slug>.md`.
- **Ledger** -> `.claude/skills/data/state/ledger.jsonl` (idea, data_asset, play, moat, test, report path).
- **Venture record** -> add a Data-angle note to `projects/assay/ventures/<slug>.md`.

## Chain
`/expand` -> **`/data`** (one angle).
